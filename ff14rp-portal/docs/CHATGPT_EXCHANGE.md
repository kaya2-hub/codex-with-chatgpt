# ChatGPT連携(イベント・セレモニー共通)

方針: **文章の理解・企画作成はChatGPT、保存・閲覧・編集・運用管理は総合DB。** 総合DBは自由文を解析しません。外部の有料APIも使いません。

## 使い方
### 新規作成
1. 総合DBの「イベント」→「ChatGPTで新規作成」(セレモニーは各対象者の「セレモニー原稿」→「ChatGPTで作成」)で **仕様書をコピー**。
2. ChatGPTの会話に貼り付け、普段どおり企画を相談。曖昧な点はChatGPTが質問します。
3. 「これでOK」「書き出して」と伝えるとJSONが出力されます(ファイル生成できる環境は `.json` ファイル、できなければコピー用の本文)。
4. 総合DBの取り込み欄へ **ファイル選択 or 貼り付け** → 「検証してプレビュー」→ 内容確認 → 「新規登録する」(下書きとして登録)。
### 既存データの再編集
1. 対象の画面で「ChatGPTで編集」→ **編集用データをコピー(仕様書＋現在のデータ)** または「JSONを書き出す」。
2. ChatGPTに貼って「このセリフを変更」「地下への移動を5分早める」等と相談 → 更新版JSONを出力。
3. 総合DBへ取り込み → **差分(追加/変更/削除/並べ替え/項目)** を確認 → 反映したい変更だけチェックして反映。
### 一箇所だけ直したいとき
アプリ上で直接編集できます(基本情報・タイムラインの各ステップ・マクロ・担当/資料・準備/注意・振り返り・セレモニー原稿)。編集は「その1項目だけ」を保存し、他は変わりません。

## 画面の使い方(UI)
- **手順パネル**: 「ChatGPTで新規作成/編集」を開くと、6ステップ(仕様書コピー→ChatGPTで作る→質問に答える→「書き出して」→JSONを取り込む→確認して登録)を、各操作ボタンと一緒に表示します。折り畳めます。
- **取り込みプレビュー**: 登録される内容(基本情報・担当・準備/注意・3列タイムライン全ステップ・マクロ全文・資料・振り返り)をすべて表示し、登録後の画面と同じ見た目です。更新時は変更前/変更後を並べ、追加=緑・変更=黄・削除=赤・競合=赤枠で区別します。
- **閲覧モードと編集モード**: 通常は閲覧モード(マクロのコピー・折り畳みは可、編集操作は非表示)。「✎ 編集モード」で編集でき、未保存の変更があるまま終了・移動しようとすると破棄確認が出ます。
- **色分け**: かや=淡いピンク、トーシン=淡い緑、タイミング・合図・共通条件=中立。

## 安全の仕組み
- **取り込める項目を限定**: イベントは名前/店舗/日付/時間/会場/概要/企画/担当/タイムライン/マクロ/準備/注意/資料/振り返り、セレモニーは呼称/内容/感謝コメント/担当/タイムライン/マクロ/準備/実施後メモのみ。**開催状態・原稿の完成・実施記録・来店記録・Ver判定・顧客の備考やDM には触れません**(JSONに書いても無視/警告)。
- **新規と更新を区別**: `op: create` は新規(下書き)、`op: update` は既存を差分更新。セレモニーは既存の原稿があるのに create すると拒否(無断上書きなし)。
- **厳格な検証**: `schema` / `version`(現在 1)/種別/必須項目/型/日付/担当者/項目種別/ID重複を検査。不正なら**保存せず**、どの項目(例 `event.timeline.steps[2].kaya[0].type`)が問題かを表示。
- **差分と衝突(3者比較)**: 書き出しJSONに含まれる `_base`(書き出し時の各項目のハッシュ)を使います。
  - ChatGPTが変えた項目だけが「変更」になり、変えていない項目は他の人の編集をそのまま維持します。
  - ChatGPTと他の人の**両方が変えた項目**は「競合」。既定は現在の値を維持で、チェックすると取り込み側を採用します。
  - 他の人が書き出し後に追加した項目はChatGPTのJSONに無くても削除扱いにしません。他の人が編集した項目を削除しようとすると競合になります。
  - `_base` が無い場合も差分を表示しますが、衝突検出ができない旨を表示します。
  - プレビュー後にデータが更新された場合は保存を拒否し、再検証を求めます。
- **ChatGPTに渡す情報**: 仕様書+そのイベント/原稿の内容のみ。セレモニーの `facts`(来店回数・Verスタンプ・演目・実施状況)は参照用で、取り込み時は無視されます。**個人の備考・DM URLは含めません**。
- **履歴**: すべての変更を `history` に記録(誰が・いつ・何を)。held後の編集は編集前の内容も保持。旧形式のタイムラインを新形式へ変換して保存する際は、元を `timelineLegacy` に退避します。

## JSON形式(バージョン 1)
共通: `{ "schema": "ff14rp.event" | "ff14rp.ceremony", "version": 1, "op": "create" | "update", ... }`

| 項目 | イベント `event` | セレモニー `ceremony` |
|---|---|---|
| 対象 | `target.occurrenceId`(update時) | `target.personId` と `target.stampValue`(7の倍数) |
| スカラー | name(新規必須), store(`diner`/`toko`/null), date(`YYYY-MM-DD`/null), startTime, endTime, venue, overview, plan, retrospective | characterName, content, thanks, postNote |
| リスト | prep[], cautions[] | prep[] |
| 項目配列(id付き) | staff[{role,duty}], macros[{title,role,body,note}], materials[{label,url,note}] | staff[], macros[] |
| タイムライン | `timeline: {version:2, steps:[{id,time,phase,cue[],kaya[],toushin[],note}]}` | 同左 |
- 列の項目(Item): `{type, text}`。`type` = `say`(セリフ) / `action`(動作) / `change`(キャラチェンジ) / `condition`(進行条件) / `intent`(演出意図) / `text`(未分類)。複数行は `\n`。
- `time` は原文の表現のまま(「22:55頃」「23時になったら」)。不明なら空文字。補完しません。
- 担当者 `role` は `かや` / `トーシン`(内部ID `Kaya` / `Toushin` も可。表記ゆれは同一人物)。
- 省略した項目は更新されません。配列項目は「指定したら全体の置換」(IDで既存と対応、ないIDは新規、配列から外したものは削除)。

実例: `docs/samples/event-sample.json`(22:00〜23時の進行。22:55頃の移動・キャラチェンジ・会話劇を含む)、`docs/samples/ceremony-sample.json`。ChatGPTに渡す仕様書そのもの: `docs/samples/chatgpt-spec-event.md` / `chatgpt-spec-ceremony.md`(`node tools/gen-spec-docs.mjs` で再生成。テストで最新性を検証)。

## 旧機能の整理
- 撤去: 「Notion/テキストからの一括取り込み(貼り付け)」「ルールベースの自由文→3列自動分類」。既存の保存済みマクロ・タイムラインは残り、表示・編集時に新形式へ変換されます(元は退避)。
- 残置: イベントマスター(従来の複製元)は互換のため「旧: イベントマスター」として折り畳み表示。GG等のテンプレート({{customer_name}}置換)は演目テンプレートとして従来どおり。
